核心功能

            
日常记录的核心功能

            
覆盖饮食录入、模型配置、健康指标追踪与本地数据管理。

          


          

            

              
🍜

              
饮食记录

              
可通过文字描述、拍照或语音输入，由 AI 估算食材热量与营养成分；不使用 AI 时也可以手动录入。

              
    
                
  • 提供文字、拍照与语音三种 AI 记录方式
    • 
                
  • 追踪蛋白质、碳水、脂肪等 13 项营养指标
    • 
                
  • 按早、中、晚、加餐分类记录
    • 
                
  • 常用菜谱可加入收藏，后续一键记入
    • 
              

            


            

              
✦

              
AI 助手与模型配置

              
提供对话式营养助手，结合饮食记录与健康目标给出建议；允许自定义模型服务商，密钥在本地加密保存。

              
    
                
  • 兼容 OpenAI、Claude、Kimi、GLM、Qwen、DeepSeek、Gemini、LongCat 八种协议
    • 
                
  • 流式输出，逐字实时显示回复
    • 
                
  • 具备多会话管理能力，可置顶、清空或删除
    • 
                
  • 记录调用次数、Token 用量与响应耗时
    • 
              

            


            

              
⚖️

              
健康追踪

              
整合体重、饮水与运动记录，结合基础代谢计算每日热量平衡。

              
    
                
  • 体重记录与历史趋势回顾
    • 
                
  • 自定义饮水目标（1200–5000 毫升）与快捷加水
    • 
                
  • 预置 29 种运动类型，按时长估算消耗热量

数据管理

              
所有记录均保存在手机本地数据库中，可随时导出备份文件，方便换机迁移与存档。

              
    
                
  • 基于 Room 本地数据库，离线可用
    • 
                
  • 一键导出 JSON 格式备份文件
    • 
                
  • 提供 WebDAV 协议云端备份与恢复
    • 
                
  • 恢复前可查看数据预览，分为全量覆盖与合并导入
    • 
              

            

          

        

      


      
      

        

          

            

              
数据保留在手机本地

              
CalorieAI 不设账号系统，没有用于收集用户数据的中心服务器。饮食、体重、对话等记录均保存在手机本地 Room 数据库中；AI 密钥通过系统级加密落盘；备份与导出完全由用户自主操作。

            

            

              

                
🔒

                
健康数据留在本机记录保存在手机本地数据库，不上传到任何服务器。

              

              

                
🔑

                
API 密钥本地加密密钥经 Android KeyStore 的 AES-GCM 加密后落盘，源码中不内置任何密钥。

              

              

                
📤

                
备份由用户触发云备份使用自主配置的 WebDAV 地址与凭据，不会自动静默上传。

功能详解

            
功能模块说明

            
介绍界面结构、数据存储位置与可选功能，所有说明与当前发布版本保持一致。

          


          
          

            
工作台
由四个核心页面构成。

            

              
首页 · 菜谱 · 概览 · 我的

              
底部导航包含四个页面。首页展示每日收支与明细：顶部为可切换日期的日历，中间为摄入概览卡片，列出「已摄入 / 目标 / 剩余」三组数值与进度条，标题随日期动态切换：当日为「今日摄入」，切换至既往日期为「昨日摄入」，切换至未来日期则为「明日目标」。下方依序展示当天的饮食与运动明细，支持左滑编辑或删除。

              
菜谱页用于管理常用食物：将核对过的菜品加入收藏后，可在「快捷复用」中按餐次筛选并一键「加入今日」，无需重复输入。每条菜谱均显示对应热量与累计使用次数。

              
概览页用于查看中长期趋势与综合统计，主要分为六个部分：

              
    
                
  • 本月活跃度12 周打卡热力图，展示每日打卡分布，并统计连续记录天数与月度活跃度。
    • 
                
  • 本月总结汇总当月摄入总热量、运动消耗与体重变化。
    • 
                
  • 数据速览集中查看今日摄入、饮水、当前体重与运动消耗四项指标。
    • 
                
  • 连续记录成长本周记录目标、已连续记录天数与成就徽章。
    • 
                
  • 菜谱相关统计已有食材、收藏数量、复用次数与临期食材提醒。
    • 
                
  • 快捷入口直达详细统计、体重历史和健康目标。
    • 
              

              
我的页用于管理个人身体档案、应用设置与数据备份，具体选项在后文展开说明。

              
在「我的 → 界面外观」中可开启简洁模式，仅保留首页与我的两项页面，详见第 08 节。

            

          


          
          

            
饮食记录
提供三种 AI 识别方式与手动录入。

            

              
录入方式与识别流程

              
点击首页右下角「+」号，可选择AI 智能识别或手动录入。

              
进入 AI 识别后，可从三种输入方式中选择：文本描述直接输入食材与分量（如「番茄炒蛋，番茄150g，鸡蛋2个，油10g」），分量写得越明确，估算结果越贴近实际；拍照识别直接拍摄食物由多模态模型分析，并可补充文字备注；语音输入由安装包内置的离线语音模型完成转写并交由 AI 分析，录音无需上传至第三方云端。

              
识别完成后进入记录详情页，展示总热量及三大宏量营养素，并细化列出膳食纤维、糖、饱和脂肪、钠、胆固醇、钙、铁、钾、维生素 A、维生素 C 等 13 项营养指标与食材明细。所有数值均可手动修改，也可让 AI 重新生成。确认无误后选择餐次（早餐、午餐、晚餐、加餐）即可保存。

              
若无需 AI 辅助，可选择手动录入。只填写食物名称与热量即可保存，营养成分与备注均为选填项；录入的菜品同样能加入菜谱中心，方便后续复用。

              
在首页列表中，向左滑动任一记录即可进行编辑或删除，删除前会二次确认以防误触。

              
    
                
  • 输入方式文本描述 / 拍照识别 / 语音输入（AI），纯手动录入
    • 
                
  • 营养追踪13 项指标：三大营养素 + 膳食纤维、糖、饱和脂肪、钠、胆固醇、钙、铁、钾、维生素 A、维生素 C
    • 
                
  • 餐次早餐、午餐、晚餐、加餐
    • 
                
  • 整理左滑编辑 / 删除；收藏菜谱后一键复用
    • 
                
  • 食材库存记录现有食材种类、数量与保质期，临期时自动发出提醒
    • 
              

            

          


          
          

            
体重记录
记录数值与可选备注。

            

              
记录与趋势跟踪

              
输入体重（公斤）并选择日期，可添加「晨起空腹」等可选备注，保存即完成记录。

              
点击「查看历史记录」可浏览或删除历史记录。体重数据将同步计入统计页中的体重变化趋势与 BMI 趋势图表，并呈现在概览页的当前指标中，同时为 AI 助手的饮食建议提供参考。

              
应用内没有单独的「目标体重」追踪项。设定健康目标时填写的目标体重用于引导阶段的方向选择与预计周期估算，日常以记录和趋势为主。

            

          


          
          

            
饮水与运动
日常水分补充与热量消耗记录。

            

              
饮水管理与运动消耗

              
饮水记录以毫升为单位。目标量默认为 2000 毫升，支持在 1200–5000 毫升范围内自定义或参考系统推荐值；支持 100、200、250、300、500 毫升快捷加水与自定义输入，并可设置按时段喝水提醒。

              
运动记录内置 29 种运动分类，涵盖跑步、骑行、游泳、力量训练等。输入时长（分钟）后，系统可自动估算消耗热量，也支持手动填写精确数值。所有运动消耗均计入当日总热量支出。

              
    
                
  • 饮水目标1200–5000 毫升，默认 2000，可参考推荐值
    • 
                
  • 快捷加水100 / 200 / 250 / 300 / 500 毫升，或自定义
    • 
                
  • 运动类型29 种，覆盖日常与训练场景
    • 
                
  • 消耗估算按时长自动估算，也可手动填写
    • 
              

            

          


          
          

            
每日统计
当日汇总、趋势变化与月度总结。

            

              
多维度统计与分析

              
统计页面包含三个标签页。概览统计汇总当日数据：摄入与目标差值、基础代谢与总消耗、净摄入量、餐次热量分布、达标天数统计，以及 13 项营养成分的详细摄入情况。

              
趋势分析支持按日、周、月三种粒度查看，时间跨度覆盖近 7 天至近 6 个月，可切换热量摄入、运动消耗、体重、BMI 与饮水五类趋势图表。

              
上月总结以月度为周期生成汇总：包含有效记录天数、最高摄入日、目标达成率、餐次热量占比、运动总消耗与体重变化幅度。

              
若开启简洁模式，统计页面将精简为三张核心卡片：近七日摄入柱状图、今日消耗（基础代谢与活动消耗）以及近期体重变化。

              
    
                
  • 概览统计今日摄入状态、餐次分布、达标统计、连续记录、13 项营养素
    • 
                
  • 趋势分析热量 / 运动 / 体重 / BMI / 饮水五类趋势，按天·周·月切换
    • 
                
  • 上月总结记录天数、最高日摄入、达标率、运动与体重月报
    • 
                
  • 活跃热力图12 周打卡热力图，展示连续记录情况
    • 
              

            

          


          
          

            
AI 配置
自主接入模型服务商与端点。

            

              
服务商协议与自定义配置

              
CalorieAI 不绑定特定模型服务商，亦不内置任何生产 API 密钥。首次启动会自动生成一条指向项目方中转服务的「GPT-5.6 Luna (默认)」配置。在「我的 → AI 配置」中点击「添加新的 AI 配置」，填写以下字段即可接入自主账号：

              
    
                
  • 协议格式OpenAI、Claude（Anthropic）、Kimi、GLM、Qwen、DeepSeek、Gemini、LongCat 八选一
    • 
                
  • API 地址官方端点或兼容自建端点；默认配置预填项目方中转服务地址
    • 
                
  • API 密钥由服务商平台控制台提供
    • 
                
  • 模型 ID服务商支持的模型标识
    • 
                
  • 图像理解开启后拍照识别使用多模态模型
    • 
              

              
配置支持添加多条并随时切换。每项配置均提供「测试连接」功能，发起验证请求并在界面返回连接状态。应用内置了 4 条「GPT-5.6 Luna」预设模板（拍照、对话、思考、文本），采用 OpenAI 兼容协议。预设模板不含内置密钥，需在任意配置中填入有效的 API Key 后方可使用。

              
为防止过度调用，默认单条配置每日上限 50 次，输入框实时显示当日剩余可用次数。「模型调用统计」页面完整记录调用日志：包含总请求量、成功率、输入与输出 Token 数、响应耗时及预估费用。

              
网络请求路径说明：自定义配置直接连接用户配置的 API 端点；默认的「GPT-5.6 Luna」配置与预设将请求发送至项目方中转服务 oneapi.sxyq27.online，并由其转发至上游模型。如需完全直连，可直接配置自有端点地址与密钥。

            

          


          
          

            
本地密钥保存
经由系统硬件级密钥库加密后落盘。

            

              
密钥存储与加密机制

              
填写的 API 密钥不会以明文写入数据库。保存时，系统在 Android KeyStore 中生成专属密钥，使用 AES/GCM 算法对密钥加密后存入本地数据库。密文字符串带有 enc:v1: 前缀，仅在内存发起请求时解密使用，磁盘不存明文。

              
KeyStore 密钥不可导出，其他应用亦无法访问。导出备份时，AI 配置默认以已加密状态写入 JSON 文件；也可在导出时取消勾选「包含 AI 配置」，使导出的备份文件不含任何密钥数据。

              
    
                
  • 加密方式Android KeyStore + AES/GCM（NoPadding）
    • 
                
  • 存储位置手机本地数据库 ai_configs 表
    • 
                
  • 密文标识enc:v1: 前缀，读取时解密、永不回显明文入库
    • 
                
  • 源码审计代码仓库不含任何内置生产密钥
    • 
              

            

          


          
          

            
简洁模式
精简页面层级与核心视图。

            

              
界面精简与保留功能

              
开启「我的 → 界面外观 → 简洁模式」后，应用收敛为首页与我的两个主页面。隐藏菜谱、概览、饮水、运动、AI 对话及拍照识别，底栏字号与图标相应放大，便于直观操作。

              
统计页面精简为三张核心卡片：近七日摄入柱状图、今日消耗（基础代谢与活动消耗）以及近期体重变化。

              
该模式适合仅需基础热量记账的使用场景。设置即时生效，切换回完整模式后所有隐藏模块与历史数据均不受影响。

              
    
                
  • 开关位置我的 → 界面外观 → 显示模式 → 简洁模式
    • 
                
  • 保留功能首页、我的、饮食记录、体重记录、核心统计
    • 
                
  • 隐藏功能菜谱、概览、饮水、运动、AI 助手、拍照识别
    • 
                
  • 默认状态关闭。开关即时生效，随时可切回完整模式
    • 
              

            

          


          
          

            
备份与恢复
本地文件导出与 WebDAV 云端备份。

            

              
备份方式与数据恢复

              
在「我的 → 备份」中提供两种备份途径。本地备份将全部数据导出为 JSON 格式文件（命名为 calorieai_backup_时间戳.json），保存路径由系统文件选择器指定，支持勾选是否包含已加密的 AI 配置。

              
WebDAV 云备份支持配置自定义服务器地址、目录、文件名及账号密码（建议使用应用专用密码），可直接上传备份并在更换设备后从云端拉取恢复。支持坚果云、Nextcloud 等通用 WebDAV 服务，应用不经由第三方服务器中转凭据。

              
恢复前系统会展示恢复预览：包含备份生成时间、各类记录条数及导入方式判断。确认时提供两种恢复模式：

              
    
                
  • 全量覆盖先清空当前记录，再按备份完整重建。备份中包含的数据项会被完全替换。
    • 
                
  • 合并导入保留当前数据并导入备份内容；相同 ID 的记录会被更新，其余记录原样保留。
    • 
              

              
「全量覆盖」将先清空本地现有数据后再写入备份内容。执行前请确认当前设备无未备份的必要记录。

帮助文档

            
使用指南与常见问题

            
包含基础功能上手指引与常见疑问解答，应用内使用手册与常见问题同步更新。

          


          

            

              
初次使用：设置身体档案

              
新手引导将依序收集身体基本指标（性别、年龄、身高、体重）、日常活动量、健康目标及减增重节奏。系统基于 Mifflin-St Jeor 公式计算基础代谢（BMR）与每日建议摄入量，作为主页热量目标基准。后续可在「我的 → 个人信息」中随时调整。

            

            

              
记录第一餐

              
在首页点击「+」按钮，选择「AI 智能识别」后输入文字、拍摄照片或语音录入。详细描述食材分量可提高估算准确度；在结果页核对数值并选择餐次后即可保存。若未配置模型，可直接使用「手动录入」。

            

            

              
接入自定义模型

              
进入「我的 → AI 配置」点击「添加新的 AI 配置」，选择对应协议（支持 OpenAI、Claude、Kimi、GLM 等八类），填入 API 地址、密钥与模型 ID，点击「测试连接」测试可用性。若需使用拍照识别，请开启「图像理解」并选用支持视觉的模型。

            

            

              
数据备份与设备迁移

              
在「我的 → 备份」中点击「创建备份」可导出 JSON 文件；或配置 WebDAV 后使用「上传云备份」。新设备安装后可从云端拉取，系统将提供数据预览并支持选择全量覆盖或合并导入。

            

            

              
启用简洁模式

              
在「我的 → 界面外观」中开启「简洁模式」，界面将精简为首页与我的两页，放大字体与图标，隐藏扩展模块，仅保留核心记账与基础统计。关闭开关可随时切回完整版。

            

            

              
应用内自动更新

              
应用启动约 1 秒后自动查询版本清单。检测到新版本将弹出更新提示，确认后自动下载、进行 SHA-256 完整性校验并调起系统安装更新。

隐私与安全

            
数据存哪、发给谁、你怎么拿回来

数据存储说明
一切记录的家，在你手机里。

            

              
本地数据库，不上传服务器

              
饮食、体重、饮水、运动、AI 对话、收藏菜谱、食材库存、调用日志——全部记录保存在手机本地的 Room 数据库中，共 12 张表；应用设置（主题、简洁模式、各项目标）存在本地 DataStore。手机不联网，这些功能照常工作。

              
CalorieAI 没有账号体系，没有自己的数据服务器，因此也不存在「我们的数据库泄露了你的健康记录」这种风险面——数据从来没离开过你的设备，除非你亲手导出。

              
    
                
  • 记录数据Room 本地数据库（12 张表：饮食、体重、饮水、运动、AI 配置、AI 对话、Token 用量、调用记录、收藏菜谱、食材库存、菜谱计划、用户设置）
    • 
                
  • 应用设置DataStore 本地键值存储
    • 
                
  • 账号体系无。不注册、不登录、不采集设备标识
    •

密钥与凭据
钥匙加密后才落盘。

            

              
AI 密钥的保存方式

              
你的 API 密钥在保存时经过 Android KeyStore + AES/GCM 加密（密文以 enc:v1: 标识），以密文形态存于本地数据库；KeyStore 密钥由系统硬件保护，不可导出、其他应用无法读取。使用时在内存中解密，不回写明文。

              
WebDAV 的地址与凭据保存在本地设置中，仅在你触发云备份时使用。应用源码中不含任何内置密钥或硬编码凭据，这一点可以直接审计仓库确认。

              
导出备份时，AI 配置默认随备份走且保持加密形态；如希望备份文件完全不包含密钥，导出时取消勾选「包含 AI 配置」即可。

            

          


          

            
备份与恢复说明
数据的去向，你来签字。

            

              
带走与找回

              
导出：一键生成 JSON 备份（calorieai_backup_时间戳.json），内含饮食、运动、体重、饮水、设置、收藏、库存、菜谱计划、AI 对话与调用日志，保存路径由你选择。

              
云备份：WebDAV 协议，服务器地址、目录、文件名、凭据全部由你填写——坚果云、Nextcloud 或任何兼容网盘均可。应用不内置、不推荐、不代理任何云服务商。

              
恢复：恢复前先看预览（备份日期、各类记录条数、每类是新增还是覆盖），然后二选一——全量覆盖（先清空再按备份重建）或合并导入（保留现有数据，同 ID 记录更新、其余保留）。选错模式有清库风险，请看清再确认。
